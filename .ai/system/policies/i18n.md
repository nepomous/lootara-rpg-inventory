# POL-I18N — Internationalization

- **TRIGGER:** Any user-visible text is added, changed or removed.
- **PARAMETERS** (from `.ai/project/context.md`): list of locales and file paths, reference locale, fallback locale, key-naming conventions.
- **WHY:** A missing key shows `undefined` silently in the UI. The fallback locale reaches most users whose device language is not supported, so it must be complete.
- **VERIFY:**
  1. No visible string literal in components; all go through the translation function.
  2. Each new/changed key exists in **all** configured locale files, added in the same change.
  3. The reference locale defines the key names (authoring convention); the fallback locale is **100% complete** at all times.
  4. Translations read naturally in the target language (no literal machine translation).
  5. Keys for dynamic content follow the project's key convention (e.g., per-entity name keys with a default value).
  6. A missing key in any locale is treated as a bug.
- **EVIDENCE:** Table of keys × locales (or the parity-script output); list of files touched.
- **ENFORCEMENT:** parity of keys: deterministic (Gate A check 5). Naturalness: agent + human.
- **OWNER:** Developer executes · Reviewer confirms · Human spot-checks languages they read.
- **ORIGIN:** legacy "Validação de Traduções".
